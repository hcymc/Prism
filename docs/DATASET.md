# 数据集

## 主数据：IndustryCorpus2

| 项目 | 值 |
| --- | --- |
| 来源 | 智源 BAAI，`BAAI/IndustryCorpus2`（HuggingFace / hf-mirror） |
| 许可 | **Apache-2.0** |
| 规模 | 中文全量约 1 TB，**已按行业分好目录**——目录名本身就是标签 |
| 本项目用量 | 316,712 篇 / 356,481,811 字 / 30 个子集 |

用它的最大理由：**标注成本为零**。文件放在哪个目录，标签就是什么，一条都不用手写。

31 个类别名（`src/domains.py`，顺序即 id）：

```

消防安全_食品安全    石油化工             计算机_通信        人工智能_机器学习
其他信息服务_信息安全 学科教育_教育        文学_情感          水利_海洋
游戏                科技_科学研究         采矿              住宿_餐饮_酒店
其他制造            影视_娱乐             新闻传媒          汽车
生物医药            航空航天             金融_经济          体育
农林牧渔            房地产_建筑           旅游_地理          法律_司法

```

前 30 个有真实样本；**第 31 个「其他」从无正样本**，模型永远学不会输出它
（这就是模糊文本只能硬选一个真类的原因，见 [NOTES.md](NOTES.md)）。

## 怎么抓

```bash
export PRISM_HOME=/data/prism

# 1. 先筛分片：只读文件末尾 4 字节，判断 parquet footer 是否完好
python dataset/scan_ic2.py
#    → $PRISM_HOME/shards_ok.json

# 2. 并发下载可用的分片，转成 prepare.py 能读的目录结构
python dataset/fetch_ic2.py --help
```

`scan_ic2.py` 解决的是一个具体的坑：**这批 parquet 有一部分是写入时没写 footer 的残片**。
文件以 `PAR1` 开头、大小和官方 API 一致，但结尾没有 `PAR1`，pyarrow 打不开。
ModelScope 官方源和 hf-mirror 上的字节完全相同，不是镜像的问题。

标准 parquet 末尾 4 字节一定是 `PAR1`，所以用 HTTP Range 只取最后 4 字节，
几 KB 流量就能判断一个分片能不能读，不用把几百 MB 下下来才发现是坏的。

## 目录格式要求

`prepare.py` 只认这一种结构，子目录名必须与 `src/domains.py` 里的 31 个名字之一**完全一致**：

```
corpus/
├─ 金融_经济/       a.txt  b.txt  ...
├─ 法律_司法/       ...
└─ （其他 28 类）
```

名字对不上的目录会被跳过并计数，不会静默混进训练集。

## 其他来源（评测用，不进训练）

| 脚本 | 用途 |
| --- | --- |
| `dataset/fetch_web.py` | 抓维基百科 / 中国新闻网的中文正文，作为「分布外文本」检验泛化 |
| `dataset/gen_deepseek.py` | 调 DeepSeek 生成 30 类各若干篇文章，做外部对照实验（需要自己的 API key） |

这两路只用来回答一个问题：**换一批和训练集来源不同的文字，掉多少点**。
实测同类语料 85%，DeepSeek 写的 150 篇只有 64%。

## 合规提醒

- IndustryCorpus2 是 Apache-2.0，但**重新分发原始语料前请自行确认上游条款**；
  本仓库不包含任何原始文本。
- `gen_deepseek.py` 会调用外部 API，key 自己出，别把 key 提交进仓库。
- 抓取脚本默认走 `hf-mirror.com`（国内可达），换网络环境时注意速率。
