# 笔记：还没搞清的事，以及踩过的坑

## 三个还没做实验的问题

写在这里，是为了下次接手时不用重新想一遍。

1. **短句补齐是否放大了标点噪声**
   手写 30 字短句在改掉全角标点后，命中率从 30% 跳到 76%，远大于 40 字切片实测的 +4.2pt。
   怀疑是「重复补齐到 512」把 `<unk>` 变成了周期性信号（同一位置反复出现），
   让注意力锁在一个假模式上。**未验证**。

2. **分布外掉点，是「文风不对」还是「题目本身模糊」**
   同类语料 85%，DeepSeek 写的 150 篇只有 64%。掉 20 个点，
   到底是模型只认训练集那种新闻体，还是那些题目本来就不好归类？**未验证**。

3. **85% 的天花板是容量不够还是标签重叠**
   分类头第一层 12.9 万步几乎没动（std 0.020 → 0.029），倾向前者之外的后者——
   即瓶颈在标签本身。但没做过消融（删掉第一层 / 加 LayerNorm / 换成 512→128→31）。**未验证**。

---

## 已经确认的事实（别再踩第二遍）

### 语料与词表

- **IndustryCorpus2 的正文里逗号句号全是半角** `,` `.`，字表 15,341 个词条里
  只有一个中文标点：`·`。没有 `，` `。` `、`。
- 后果：真实文本直接喂进去，每个 `，` 都变成 `<unk>`；而 `<unk>` 在训练数据里出现 0 次，
  向量是随机初始化的。所以推理前必须做全角→半角归一化（`src/textproc.py`）。
- 这个归一化的实际收益：**命中率变化在噪声内，置信度稳定 +0.03~0.06**。
  也就是说，不做归一化，代价是「模型变得没底」，不是「判错」。

### 长度

- 训练时模型永远见 512 字，所以**短输入属于没见过的形态**。
- 30 字 44%，512 字 82–88%。
- 把同样 30 字**重复补齐**到 512，命中 29.2% → 62.5%。信息一个字没多，只是长度对了。
- 但补齐会把置信度一起抬高（0.31 → 0.74），拿概率当权重时要留意。

### 类别

- 第 31 类「其他」无训练样本 → 模型不会说「不确定」。
  一篇写城市一天生活的散文被判成「住宿_餐饮_酒店」93%，因为文里有菜市场、面馆、奶茶、烤串。
- 类目重叠是硬天花板：计算机_通信 50%、科技_科学研究 60%。
  **不是分类头不会分，是那几堆向量本来就没分开。**

### 工程

- `train.log` 必须用追加模式（`a`）。曾经用 `w`，每次 `--resume` 把历史曲线清空。
- Windows 的 `SO_REUSEADDR` 允许两个进程绑同一端口，**后绑的那个收不到连接**。
  端口"占用成功"不代表能服务，用 `netstat -ano` 看 PID。
- 访问本机端口一律 `curl --noproxy '*'`，否则会被本机 HTTP 代理拦成假响应
  （表现为 502 或空 body，很容易误判成服务挂了）。
- 判断常驻进程死活**看日志 mtime 是否在增长**，不要依赖 `tasklist`——
  桌面会话的进程在沙箱工具里可能根本看不到。
- 用 `hidden` 属性隐藏元素前，先确认没有作者样式给 `display` 赋过值
  （`.inline-check { display: inline-flex }` 会盖掉 `[hidden]`）。
- 本机 loopback 不走防火墙：**只测 127.0.0.1 等于没测**，要从第二台机器打。

### ONNX 与部署

- torch 2.2 的 `scaled_dot_product_attention` 导不出 ONNX，必须展开成显式 matmul。
- 这台 CPU 没有 `avx512_vnni`，int8 理论上不该快，实测仍快 30%
  （fp32 要搬 3.4 倍权重内存）。
- 2 vCPU 可能只是**一颗物理核的两个超线程**，开 2 线程反而比 1 线程慢。
- Windows 上 onnxruntime 需要 VC++ 2015-2022 运行库，没有会报 `DLL load failed`。
  Python 3.8 只能装 `onnxruntime<=1.17.3`。
- 日志文件头要带 UTF-8 BOM，否则 PowerShell 5.1 的 `Get-Content` 按 ANSI 解，中文全乱码。
